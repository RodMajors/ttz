# 活动二次迭代 11-21 号修改报告

- **报告日期：** 2026-11-21
- **项目：** TTZ 公会站（`ttz` 前端、`ttz-server` 后端）
- **范围：** 活动二次迭代第二至第四期，以及战术方案草稿/版本的管理入口

## 总体结论

第二期的 8×5 Boss 团队分配、报名绑定和名单/快照锁定已实现；第三期的任务类型、技能目录、顺序分配、固定时间轴、后备执行者和冲突校验已实现；第四期已在战术模板和活动快照中接入 React Konva 站位画板，支持预设场地图、形状/连线/箭头/文字、槽位标记、查看模式和 PNG 导出。

战术草稿也增加了可持续访问的管理员管理页。创建草稿后可从“团本进度 → 战术方案管理”重新进入，并继续编辑、复制版本、发布/审核、设默认或归档/恢复。

## 分期完成内容

### 第二期：团队分组、人员绑定与快照锁定

- 每个 Boss 活动快照维护独立的 **8 组 × 5 席**团队框架；既有快照通过迁移补齐 40 个席位，新建快照直接生成席位。
- 未分配池只展示确认及替补报名。负责人可以使用 HTML 拖放，也可以采用点击成员后点击席位的方式分配；后者可用于触屏和不支持拖动的操作方式。
- 战术抽象槽位可以绑定本场报名，支持解除和重新绑定；团队席位与抽象战术槽位分开保存，同一成员可以在两类用途间被引用。
- 分配更新纳入活动版本和快照修订号的并发检查；服务端确认报名属于当前活动且状态为确认/替补，限制位置范围并校验槽位归属。
- 锁定名单时在事务中锁定 Boss 快照，并固化用户名、角色、服务器、职业和本场专精等展示字段。解锁保留报名绑定，清空锁定时展示值并恢复编辑状态。
- 任务执行者、后备执行者或目标槽位未绑定有效报名时，拒绝锁定。玩家技能若限定职业/专精，也会在锁定时针对实际执行者校验。

### 战术方案、草稿和版本管理

- 新增管理员可访问的战术方案管理页，可按进度计划浏览全部启用和归档方案及其草稿/已发布版本。
- 新增/编辑方案名称和说明、复制当前版本创建草稿、进入版本编辑器、发布草稿、将方案设为默认、归档和恢复均有明确入口。
- 归档采取软归档，不硬删除历史方案；归档默认方案时会清除默认指针。旧活动使用的是物理快照，不会随模板变更。
- 发布版本不可变；发布人/审核人信息在管理页展示。当前系统没有单独的“编辑者/审核者”角色，**管理员发布即代表审核通过**，发布者信息被记录。
- 已审核成员仍可查看已发布版本；草稿编辑、发布、归档及技能目录维护由服务端管理员权限拦截，不只依赖前端隐藏按钮。

### 第三期：任务、技能目录和时间轴

- 新增可扩展任务类型目录，迁移内置打断、减伤、分担、驱散、控制、站位和自定义类型；内置类型标记为系统项，不可删除。管理员可新增公会自定义类型。
- 新增机制技能和玩家技能目录，支持维护名称、游戏技能 ID、来源、职业/专精限制、图标和来源说明，并可停用；管理员可在版本编辑器中管理目录。
- 顺序任务和时间轴任务使用关系表保存，字段覆盖任务类型、机制技能、玩家技能、执行者/目标/后备槽位、说明、顺序、时间偏移、窗口、阶段、施法轮次和提前提醒。
- 保存时校验任务引用的槽位、启用的任务类型、技能来源类型，并检测同一执行者时间轴区间重叠；使用闭区间边界逻辑（相邻时间窗口不视作重叠）。
- 从模板版本创建活动时，任务与技能名称一同物理复制到 Boss 快照。活动详情按顺序和时间展示执行计划，并将槽位解析为当前绑定成员；锁定名单时再次校验主执行者、后备执行者和目标槽位。
- 技能目录不会自动从外部游戏数据源导入；本期提供管理员手工维护 CRUD/停用入口，避免引入未经校验的外部映射。

### 第四期：站位画板

- 在战术模板版本编辑器和本场 Boss 执行快照中均接入 React Konva 画板，并通过客户端动态加载避免 SSR 阶段加载 Konva。
- 预设圆形、方形、六边形和纯色场地；活动快照画板额外允许输入自定义地图图片 URL。
- 支持圆形、矩形、连线、箭头、文字和抽象槽位标记；标记只保存 `slotKey`，展示时再解析名称，避免将昵称写死在画布 JSON 中。
- 模板发布后以及活动/名单锁定后画板只读；负责人可切换查看模式、编辑并保存活动快照画板，支持 PNG 导出。
- 自定义远程图片受浏览器 CORS 策略影响；如果图片服务器不允许跨域读取，画板仍可显示图片，但 PNG 导出会提示失败，可切换内置场地图导出。

## 后续可继续完善

- 活动快照目前可调整团队席位、报名绑定、抽象槽位绑定和站位画布；任务/时间轴结构来自已发布模板的物理复制，**尚未提供在单场活动中新增、删除或改写任务行的专用界面/API**。这不影响活动报名与任务槽位绑定、执行计划展示和名单锁定校验，可作为下一轮单场执行快照编辑增强。
- 战术方案与版本历史可查询和软归档；单个已发布版本不做硬删除或改写，发布版本继续遵守不可变原则。
- 本期没有自动同步游戏技能目录；如果后续有经校验的游戏数据源，可补充批量导入/刷新和图标资产同步。
- 当前名单历史只记录锁定时快照，不记录逐次调整的审计日志。

## 启动与部署提示

1. 应用 API 及数据库 schema 更新，先运行 `pnpm db:migrate`，确认迁移成功。
2. 构建并重启 API/Worker，再部署 Web。此次迁移不需要清库或 reset。
3. 在管理员账号下打开“团本进度 → 战术方案管理”，确认现有草稿入口及归档/发布操作。
4. 新建草稿时为任务添加执行槽位；创建活动并完成确认名单、团队分配和槽位绑定后锁定名单。锁定失败时按 API 提示补齐未绑定的主/后备执行者或修正技能职业/专精。
5. 站位画板自定义图片需来自允许浏览器跨域访问的图片 URL；否则改用内置场地图以确保 PNG 导出正常。
